How careful should it be?

One setting decides what AI tools may do with a key on their own.

RelaxedAnything goes. Deleting things and moving money out (refunds, payouts, transfers) ask you first.
Balanced defaultCalling a model or taking a payment just works. Deletes, money out, and key, billing or account changes ask you first.
StrictEach provider's cautious default, such as Stripe read-only. Best for keys you share.
Since 0.1.5: revealing a key, approving a request or widening access needs your password or Windows Hello. Any program on your machine can read the session token, but that token alone can no longer do any of these. 0.1.6 adds taking over an AI tool's connection to that list, and tells you when a new AI tool connects.

What a handle can do

Each handle carries its own rules, explained in plain English and enforced before anything leaves your machine.

Paste and done

A key's shape tells Unseenkey which of 65 providers it belongs to. Allowed websites fill in, and one read-only request checks that it works.

Rules per handle

Presets per provider: stripe:payments takes payments and refuses refunds and payouts. Paths, methods, time windows, expiry, approvals.

Hard caps

--cap 500/day: the 501st request is refused before it leaves the machine. Projects get a daily limit across all their keys.

Canaries

--canary makes a handle that never works. Plant it in .env.example; any use means someone has your files, and the vault locks.

Live approvals

Sensitive calls wait for you: allow once, always allow, or don't allow. Confirmed with Windows Hello or your password.

Projects

Keys grouped by the app that uses them. AI tools working in a project's folder see only that project's keys.

Incident responses

A burst of refused requests throttles, pauses, asks you, or locks the vault. Your choice per handle; one click to resume.

Camouflage handles

Handles shaped like the provider's own keys (sk-proj-usk-…) for SDKs that check formats. Every format carries the usk marker.

AWS and OAuth2

boto3, the AWS CLI and the JS SDK sign with a placeholder; the broker re-signs with the real key. Refresh tokens stay in the vault.

Tamper-evident log

Every call, allowed or refused, written before the response returns. A hash chain plus a keyed head catches edits, gaps and deleted entries.

Activity in plain words

"Claude Code used openai · OK". Grouped by day, with filters and search. Click any entry for the technical record.

Desktop app

Projects, keys, agent access, approvals and activity. Windows Hello, locks when idle (5 minutes to 4 hours), on sleep and screen lock. Signed auto-updates.

    Security, and what it does not do

    Everything here is in the open: the code, the threat model and the disclosure policy.

    Encrypted vault

    Argon2id (256 MiB) and XChaCha20-Poly1305. Keys locked in memory and wiped on lock. A 24-word recovery phrase; no escrow, no support-desk recovery.

    Owner confirmation

    Revealing a key, approving a request or widening access needs your password or Windows Hello, not just a token any program could read.

    Fail closed

    Each key is locked to its provider's hosts. Browser-origin requests, unmatched requests and anything the broker cannot classify are refused.

    Scrubbing

    The real key is removed from responses, including gzip, brotli and deflate replies, and from logs and error messages. A handle never reaches the provider.

    Erased, not just deleted

    Replacing or deleting a key purges every old version from the vault file, so an old copy of the file cannot give it back.

    Signed releases

    Every archive has a Sigstore signature and an SBOM; desktop updates are signed. Every CI action is pinned to an exact commit.

    What it does not do. It is alpha software and not yet externally audited, so use it with keys you can rotate. It stops accidental leaks and limits what misuse can do. A program running as you on an unlocked machine can still use keys within the rules, but it cannot take the key away or approve its own requests. It is not a sandbox; for a hostile agent you also want one.

    Questions

    Is it free?

    Yes. The local app, the CLI and every feature on this page are free and open source under Apache-2.0. The hosted part that is coming next, for sharing keys with people you hire, will be paid. If Unseenkey is useful to you, sponsoring it on GitHub pays for a first external security audit.

    Does it work with my tools?

    Claude Code, Claude Desktop, Cursor and Windsurf connect in one click. Any SDK that lets you set its API address works, which covers OpenAI, Anthropic, Stripe, AWS and most others. Tools that cannot change their address can use usk run, which is weaker: that one process sees the key, but its output is scrubbed and logged.

    Does it slow requests down?

    It adds one hop inside your own machine. Measured on a Windows laptop against a local mock server: 0.4 ms at the median and 1.9 ms at p99.

    What if I forget my password?

    When you create the vault you get 24 recovery words, shown once. Write them down. There is no other way back in, by design.

    Can I use it on servers or in CI?

    Not yet. Today it is built for your own machine: development and AI tools.

    Why should I trust it with my keys?

    Your keys never leave your machine. There is no server, no account and no analytics. The code, the threat model and the release signatures are public. It has not had an external audit yet, so start with keys you can rotate.
